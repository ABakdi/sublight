# Audit — Security baseline, pass 2 (pre-beta)

- **Type:** security
- **Opened:** 2026-09-29 · **Closed:** —
- **Status:** `open`: every finding fixed (S1 for the installed path); the native host and install.sh still to re-check ([M06b.15](../plan/milestones/06b-One-Install.md))
- **Trigger:** [my review of the Beta-1 build](../checkpoints/Beta-1-Checklist.md#9-review-after-using-the-build-2026-09-29): audits before committing to a beta.

## 1. Scope

- In: everything [pass 1](2026-09-Security-Baseline.md) covered, re-verified, and the 19 commits since it (after `a6a69b0`): remote media resolution, ffmpeg, translation parsing, live translate, caption style, the content script and overlay frame, and the Player's saved fetch hints.
- Out: the same as pass 1. Also out: the native host and `install.sh` ([M06b](../plan/milestones/06b-One-Install.md)), which don't exist yet; both are audited when built (M06b.15).

## 2. Pass criteria

The [security baseline plan](Security-Baseline-Plan.md), sections A–G. Also: no pass-1 fix has regressed.

## 3. Evidence gathered

- A code review of the whole engine boundary, pairing, the relay, player-server, the extension service worker, the content and offscreen message handling, the Player hand-over and the prompts, with file:line evidence per criterion.
- `pnpm audit --prod`: no known vulnerabilities.
- A secrets grep over tracked files (keys, tokens, PEM, cloud key prefixes): none. The only key is the dev extension's **public** key, which is expected.
- `isPrivateAddress` exercised with tsx on IPv6 encodings of private addresses (S9).
- Environment: `master` at `c0ed0e5`, engine/extension/Player 0.1.0.

**Pass-1 fixes re-verified:** F1–F16 all hold (relay content types and sandbox, worker secrets, extension-page-only messages, hand-over confirmation, public-address checks, the ffmpeg protocol whitelist, header CR/LF, body limits, relay bounds, prompt neutralizing, binary checksums, retention and cache clear, dev origins, `no-store`, file modes). Constant-time token compares, Host/Origin guards on HTTP and on the WS upgrade, the CORS allowlist and one-time pairing claims are unchanged. There is no `innerHTML`, `eval` or `postMessage` in apps or packages, and no `externally_connectable` or `web_accessible_resources`. **Still open as scheduled:** F18 (open shadow roots), F19 (orphan offscreen documents), F20 (relay follows redirects), F22 (no WS connection cap).

## 6. Lessons for the project

- A check done once and used later is only as good as what happens between. The URL check (S3) and the hand-over validation (S2) both passed pass 1 and both leak through a second path: a re-resolve, or a saved and replayed hint.
- "Content scripts don't touch the token" should be enforced by the storage area, not by convention (S1).
